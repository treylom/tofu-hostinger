# 서버에 봇 올리기 — 전체 안내 (`:help`)

> **이 문서는 「읽으면서 따라하는」 안내서다.** 다른 루트(`:vps`·`:cc`·`:bot`·`:std-bot`)는 한 단계씩 물어보고 결과를 판정하는 방식이지만, 여기는 **처음부터 끝까지 쭉 읽히도록** 되어 있다. 화면에 띄워놓고 그대로 따라가면 된다.
>
> **소요**: 처음이면 40~60분. 결제·비밀번호 만들기에서 시간이 제일 많이 든다.
> **준비물**: 카드(서버 요금) · 디스코드 계정 · 비밀번호 관리자(권장)
> **출처 라벨**: 4단계(인증) 절차는 2026-08-20 라이브 VPS 실측 로그 기반으로 교정됨.

---

## 0. 먼저 — VPS 가 뭔가

**내 컴퓨터를 끄면 봇도 멈춘다.** 이게 출발점이다.

봇은 프로그램이라 누군가는 계속 켜두어야 하는데, 내 노트북은 밤에 닫고 다닌다. 그래서 **24시간 켜져 있는 남의 컴퓨터를 빌린다.** 그게 VPS(Virtual Private Server, 가상 사설 서버)다.

「가상」인 이유는 진짜 컴퓨터 한 대를 통째로 빌리는 게 아니라, 큰 컴퓨터 한 대를 여러 칸으로 나눠서 그중 한 칸을 쓰기 때문이다. 칸끼리는 서로 안 보인다.

세 가지만 알면 된다:

| | |
|---|---|
| **화면이 없다** | 마우스로 클릭하는 바탕화면이 없다. 글자로 명령을 쳐서 쓴다 |
| **끄지 않는다** | 내가 접속을 끊어도 그 안의 프로그램은 계속 돈다 — 이게 우리가 돈을 내는 이유다 |
| **월세다** | 한 달 단위로 빌린다. 안 쓰면 해지한다 |

## 1단계 — 서버 사기

Hostinger 사이트에서 **VPS 메뉴 → KVM 플랜**을 고른다.

| 플랜 | 사양 | 이럴 때 |
|---|---|---|
| KVM 1 | 1 vCPU · 4GB | 봇 하나만 돌린다 |
| **KVM 2** | 2 vCPU · 8GB · 100GB | 봇 여러 개 — 넉넉하다 |

기간을 고르고 결제한다. 카트 화면의 **할인 코드 칸**이 쿠폰 넣는 자리다.

결제가 끝나면 서버를 만드는 단계가 나온다. 여기서 **운영체제는 Ubuntu 24.04 LTS** 를 고른다.

그 다음 **root 비밀번호**(서버 관리자 비밀번호)를 정하라고 한다. **길고 복잡하게 만들어서 비밀번호 관리자에 저장해 둔다.** 바로 다음 단계에서 쓴다.

**이렇게 나오면 성공**: 관리 화면(hPanel)에서 서버 상태가 **Running**, IP 주소(숫자 네 덩이, 예: `203.0.113.10` 모양)가 표시된다.

> 🔴 **여기서 제일 많이 틀린다**: 값이 싼 「Business」 상품은 VPS 가 **아니다.** 「공유 호스팅」이라는 다른 상품이고, 그걸로는 봇을 못 돌린다. 반드시 **VPS 메뉴 → KVM** 으로 들어가야 한다.
>
> 서버를 막 만들었으면 1~2분은 부팅 중이라 접속이 안 된다. 정상이다.

## 2단계 — 서버에 들어가기 (제일 헷갈리는 단계)

**터미널**(맥) 또는 **PowerShell**(윈도우)을 연다. 그리고 `<서버 IP>` 자리에 내 서버 번호를 넣어 친다:

```
ssh root@<서버 IP>
```

처음 접속하면 `Are you sure you want to continue connecting?` 라고 묻는다. **`yes`** 라고 치고 엔터.

그 다음 비밀번호를 묻는다.

> 🔴 **비밀번호를 쳐도 화면에 아무것도 안 나온다. 그게 정상이다.**
> 별표(`*`)도 안 뜬다. 안 먹은 게 아니니 그대로 치고 엔터를 누르면 된다.
> 이걸 모르면 「입력이 안 되네?」 하고 몇 번씩 다시 치게 된다.

### 들어갔는지 어떻게 아나 — 맨 앞 글자를 본다

접속이 되면 **줄 맨 앞이 바뀐다.** 이게 유일한 신호다:

```
tofu@내컴퓨터:~$        ← 여기는 내 컴퓨터(맥 터미널)
PS C:\Users\이름>       ← 여기는 내 컴퓨터(윈도우 PowerShell)
root@srv1234567:~#      ← 여기는 서버 안
```

**`root@` 로 시작하면 이미 서버 안에 있는 것이다.** (PowerShell 도 기준은 같다 — 맨 앞이 `PS C:\...` 에서 `root@...` 로 바뀌는지만 본다.)

> 🔴 **가장 흔한 오해**: 접속에 **성공했는데 성공한 줄 모르고** 비밀번호를 한 번 더 친다.
> 그러면 이렇게 나온다:
>
> ```
> root@srv1234567:~# 내가친비밀번호
> 내가친비밀번호: command not found
> ```
>
> 비밀번호는 `password:` 라고 **물어보는 그 한 줄에만** 넣는 것이고, 들어온 뒤에는 그 자리가 **「명령어 치는 자리」**다. 그래서 비밀번호를 명령어로 알아듣고 「그런 명령 없다」고 답한 것이다.
>
> ⚠️ 이때 비밀번호가 화면에 **그대로 찍힌다.** 화면 공유나 녹화 중이었다면 그 비밀번호는 바꾸는 게 안전하다 — 서버 안에서 `passwd` 를 치면 바꿀 수 있다.

지금 어디 있는지 확인하려면 `hostname`, 나가려면 `exit`.

### 비밀번호 없이 들어가기 (권장)

매번 비밀번호를 치는 게 번거로우면 **열쇠 파일(SSH 키)** 을 쓴다.

```
ssh-keygen -t ed25519
```

질문이 몇 개 나오는데 **전부 엔터**로 넘겨도 된다.

만들어진 **공개키**를 복사한다:

- 맥: `cat ~/.ssh/id_ed25519.pub | pbcopy`
- 윈도우: `Get-Content ~/.ssh/id_ed25519.pub | Set-Clipboard`

그 값을 **hPanel → 내 VPS → Settings → SSH keys → Add SSH key** 에 붙여넣고 저장한다.

> 🔴 **비밀키(`id_ed25519`, `.pub` 안 붙은 것)는 만든 컴퓨터 밖으로 절대 옮기지 않는다.** 서버에도, 채팅에도, 메일에도.

**안 될 때**

- `Connection refused` / `timed out` → ① IP 를 다시 확인(한 글자만 달라도 실패) ② 서버가 Running 인지 확인 ③ 방금 만든 서버면 1~2분 기다렸다 다시
- `Permission denied (publickey)` → 등록한 공개키와 내 비밀키가 짝이 아닌 경우가 대부분. `cat ~/.ssh/id_ed25519.pub` 로 나온 한 줄이 hPanel 에 등록된 값과 **완전히 같은지** 대조. 급하면 비밀번호 접속으로 먼저 들어가도 된다

> 보안 보강(SSH 키 등록·비밀번호 접속 끄기)은 이 문서 범위 밖이다 — 서버를 계속 운영할 거면 별도로 해두기를 권장한다.

## 3단계 — 기본 도구 설치

서버 안에서 (`root@` 프롬프트인지 확인하고) 한 줄:

```
apt update && apt install -y git tmux curl python3.12-venv
```

**이렇게 나오면 성공**: 설치 글자가 주르륵 흐른 뒤 프롬프트로 돌아온다. 일부가 `already the newest version` 이라고 해도 정상이다 — 「이미 깔려 있다」는 뜻이다.

## 4단계 — Claude Code 설치·인증

봇의 본체가 될 프로그램이다. https://claude.ai/code 안내를 따라 설치한다.

설치 후 인증:

```
claude auth login
```

서버엔 브라우저가 없으므로:
① 터미널에 표시된 URL 을 복사해 → **내 컴퓨터** 브라우저에서 열어 로그인
② 화면에 나온 코드를 복사 → 터미널의 Paste code 프롬프트에 붙여넣기

**확인**:

```
claude auth status
```

**이렇게 나오면 성공**: `loggedIn: true` / `authMethod: claude.ai`

> 🔴 화면 글자로 판정하지 말 것. 인증 화면에서 `Invalid code.` 가 떴다가 곧바로 `Login successful.` 이 이어지는 경우가 있다. **`claude auth status` 결과로 판정한다.**
> 🔴 코드가 길어 일부만 복사되면 나는 에러다 — 전체를 다시 복사해 붙여넣기.

## 5단계 — 봇 올리기

여기부터가 봇이다. 일곱 걸음이고, **순서를 지켜야 한다.**

### 5-1. 실행기 설치 (bun)

```
apt install -y unzip
curl -fsSL https://bun.sh/install | bash
export PATH="$HOME/.bun/bin:$PATH"
```

마지막 줄은 `.bashrc` 에도 넣어둔다(다음에 접속해도 유지되게):

```
echo 'export PATH="$HOME/.bun/bin:$PATH"' >> ~/.bashrc
```

**확인**: `bun --version` → **1.3.x 이상**

> 🔴 `unzip` 을 먼저 안 깔면 `error: unzip is required to install bun` 으로 죽는다.
>
> 🔴 **이 단계를 건너뛰면 뒤에서 「죽지 않고 조용히 안 되는」 상태가 된다.** 프로세스는 살아 있고 화면도 멀쩡해서 「봇이 꺼졌나?」와 구별이 안 된다. 반드시 여기서 확인하고 넘어간다.

### 5-2. 디스코드 플러그인 설치

```
claude plugin marketplace add anthropics/claude-plugins-official
claude plugin install discord@claude-plugins-official
```

**확인**: `claude plugin list` → `discord@claude-plugins-official / Status ✔ enabled`

> 🔴 첫 줄(marketplace 등록)을 건너뛰면 둘째 줄이 실패한다. 한 줄 빠뜨려서 실패한 사례가 실제로 있었다.

### 5-3. 토큰 넣기 — **이름을 정확히**

> 🔴 토큰은 화면에 띄우지도, 어디에 보내지도 말 것 — 화면 공유·녹화 중이면 이 구간은 멈췄다가 재개한다.

```
mkdir -p ~/.claude/channels/discord && chmod 700 ~/.claude/channels/discord
nano ~/.claude/channels/discord/.env
```

편집기가 열리면 **한 줄** 쓴다:

```
DISCORD_BOT_TOKEN=여기에토큰
```

`Ctrl+O` → 엔터(저장) → `Ctrl+X`(닫기). 그리고:

```
chmod 600 ~/.claude/channels/discord/.env
```

**확인** (값을 화면에 띄우지 않고 확인하는 방법):

```
grep -c '^ *DISCORD_BOT_TOKEN *=' ~/.claude/channels/discord/.env
ls -l ~/.claude/channels/discord/.env
```

**이렇게 나오면 성공**: `1` / `-rw-------`

> 🔴 **이름이 두 가지라 헷갈린다.**
> 수업용 미니 봇은 `DISCORD_TOKEN`, **표준 봇은 `DISCORD_BOT_TOKEN`** 이다.
> 이름이 어긋나면 **에러도 없이 연결만 안 된다.**
>
> 🔴 **폴더 이름도 정확히** — 표준 봇은 `~/.claude/channels/discord/` 를 본다. 봇 이름을 붙여 `discord-내봇/` 같은 폴더를 만들면 「쓰지 않는 잔여물」로 취급된다.

### 5-4. 첫 실행 통과

처음 한 번은 **대화형으로 실행**해서 테마 → 폴더 신뢰 → 화면 설정 마법사를 통과시킨다.

> 🔴 이 단계는 **자동화 스크립트에서만 막힌다.** `claude -p "..."` 같은 비대화 호출은 마법사를 안 거치고 지나가므로, 사람이 손으로 하면 이 함정을 못 만난다.

### 5-5. 봇 켜기

```
tmux new -s bot
claude --channels plugin:discord@claude-plugins-official
```

켜지면 **`Ctrl+b` 를 누르고 손을 뗀 다음 `d`** 를 눌러 빠져나온다.

> 🔴 **`exit` 나 `Ctrl+c` 로 나가면 봇이 같이 죽는다.** `Ctrl+b` → `d` 는 「방은 그대로 두고 나만 나간다」는 뜻이다. 다시 들어가려면 `tmux attach -t bot`.

**확인** — 봇의 실행기가 상주하는지 본다. 아래 명령이 1건 이상 = 정상(띄운 세션 수만큼) · 봇이 안 붙는데 2건 이상이면 옛 세션 잔존(A5) 의심. 아무것도 안 나오면 5-1(bun) 이나 5-3(토큰)으로 돌아간다.

```
pgrep -af 'bun run --cwd.*discord'
```

> 🔴 **서버는 보통 root 계정이라 개인 PC 의 기동 명령을 그대로 복사하면 안 뜬다.**
> `--dangerously-skip-permissions` 는 root 에서 거부된다 — `cannot be used with root/sudo privileges for security reasons` 를 내고 즉시 종료한다.
>
> **이건 그나마 친절한 고장이다.** 즉시 죽고 이유까지 말해준다. 이 문서의 다른 🔴 들은 대부분 아무 말 없이 조용히 안 된다.
>
> · 그냥 대화 용도라면 **그 옵션 없이** 띄우면 된다.
> · **정석은 비-root 사용자를 새로 만들어 쓰는 것이다** — 서버를 계속 운영할 거면 이 경로를 우선으로 고려한다.
> · 🔴 **위험 고지**: 아래 조합(`IS_SANDBOX=1` + `--dangerously-skip-permissions`)은 인터넷에 열린 서버의 root 에서 안전장치(권한 확인)를 끄는 것이다. 그냥 대화 용도면 이 옵션 없이 띄우면 된다.
> · 꼭 root 에서 켜야 하면 `IS_SANDBOX=1` 을 앞에 붙인다. (`--permission-mode bypassPermissions` 도 root 에서 **똑같이 거부**된다 — 이 대안은 이미 시험해봤고 안 된다.)
>
> 🔴 **켜는 시점에 토큰과 bun 이 준비돼 있어야 한다.** 준비 안 된 상태로 먼저 켠 세션은 그 상태를 물고 있어서, **나중에 고쳐도 그 세션에서는 안 붙는다.** 조건을 갖춘 뒤 **세션을 새로 띄운다.**

### 5-6. 접근 허용 — **이걸 안 하면 완전히 침묵한다**

> ⚠️ 이건 셸 명령이 아니라 Claude 세션 **안**에서 치는 슬래시 커맨드다 — `tmux attach -t bot` 으로 방에 다시 들어가 Claude 프롬프트에 입력한다.

```
/discord:access                              # 지금 상태 보기
/discord:access allow <내 디스코드 user_id>   # 나에게 DM 허용
/discord:access group add <채널 id>           # 서버 채널 허용
```

**확인은 반대로 셸에서**: `Ctrl+b` → `d` 로 나온 뒤 `cat ~/.claude/channels/discord/access.json` 에 내 id 와 채널 id 가 들어 있다.

> 🔴 **수강생이 「봇이 죽었다」고 오해하는 1순위 자리다.**
> 허용 목록이 비어 있으면 멘션을 해도 **아무 반응이 없고 기록도 안 남는다.** 봇 자신은 이렇게 알고 있다: `Nothing can currently reach you: the allowlist is empty.`
>
> 수업용 미니 봇에는 이 잠금장치가 없어서 아무 멘션에나 답한다. **미니 봇을 먼저 해봤다면 여기서 제일 크게 당황한다.**

### 5-7. 말 걸어보기

허용한 채널에서 `@봇이름 안녕?` 이라고 쳐본다.

**이렇게 나오면 성공**: **대화형 답**이 온다. (미니 봇처럼 정해진 명령어가 아니라, 사람 말에 답한다.)

> 🔴 **조용하면 두 가지를 먼저 본다.**
> ① **서버에 초대한 것과 채널에 초대한 것은 다르다.** 서버(길드)에 봇이 들어와 있어도, **그 채널에 따로 초대**하지 않으면 못 받는다. 5-6 에서 허용 목록을 열었어도 마찬가지다.
> ② 봇 계정으로 말을 걸어 시험하는 경우라면 별도 준비가 하나 더 필요하다. **사람 계정으로 먼저 시험**하는 게 빠르다.

## 막혔을 때 — 「조용히 안 되는 것」 8가지

**이 길의 고장은 대부분 에러를 안 낸다.** 그래서 **「에러가 안 났으니 잘 된 것」이 여기서는 성립하지 않는다.**

### A군 — 아무 말 없이 안 되는 것 (6가지)

| | 무엇 | 증상 |
|---|---|---|
| A1 | bun 이 없다 | 프로세스는 살아 있는데 안 붙는다 |
| A2 | 토큰 이름·폴더가 다르다 | `DISCORD_TOKEN`(미니) ≠ `DISCORD_BOT_TOKEN`(표준) |
| A3 | 허용 목록이 비었다 | **완전 침묵.** 오진 1순위 |
| A4 | 채널에 초대를 안 했다 | 서버 소속 ≠ 채널 접근 |
| A5 | 먼저 실패한 세션 | **고쳐도 그 세션은 그대로** |
| A6 | 고친 파일이 실제로 도는 파일이 아니다 | **고쳤는데 그대로** |

> ⚠️ **A5·A6 이 제일 나쁘다.** A1~A4 는 「안 고쳤으니 안 되는」 것이라 고치면 풀린다. 그런데 A5·A6 은 **고친 뒤에도 그대로**라서, 자기가 제대로 고친 게 맞나 의심하게 만든다.
>
> **막히면 이 질문을 던진다 — 「내가 고친 자리가, 실제로 실행되는 자리인가?」**

### B군 — 즉시 죽고 이유도 말해주는 것 (1가지)

**B1. root 계정에서 거부** — 5-5 참조. 이건 화면에 이유가 뜬다.

**A군을 이해하는 기준점으로 쓰면 된다: 「이건 이렇게 알려준다. 그런데 위의 여섯은 안 알려준다.」**

### C군 — 사람이 하면 안 보이는 것 (2가지)

**C1. 첫 실행 마법사** — 손으로 하면 그냥 지나가는데, 자동화 스크립트에서만 멈춘다.

**C2. 폴더 신뢰 질문은 매번 다시 뜬다** — 「Is this a project you created or one you trust?」 는 한 번 통과해도 저장되지 않아 **매 기동마다** 다시 뜬다(실측 3/3). 손으로 켤 땐 `1` 누르고 지나가면 그만이지만, 스크립트·alias 로 켜면 이 화면에서 에러 없이 조용히 멈춘다 — 「봇이 안 켜졌다」 오판 1순위 자리.

## 보안 — 이것만은

- **비밀번호·토큰을 화면에 띄우지 않는다.** 확인은 값이 안 보이는 방법으로 (개수 세기, 권한 보기)
- **화면 공유·녹화 중이면 토큰 발급 화면에서 멈춘다.** 나중에 모자이크로 가리는 건 소용없다 — 원본에 값이 남는다
- **비밀키는 만든 컴퓨터 밖으로 안 나간다**
- 토큰이 한 번이라도 노출됐으면 **바로 새로 발급**받는다. 옛 토큰은 그 즉시 죽는다

## 부록 — 화면 아래 상태줄 (선택 설치)

강의 화면 아래에 보이는 `◆ Sonnet │ … │ 5h: 10%` 한 줄은 **`uppinote20/claude-dashboard`**(MIT) 라는 상태줄 도구다 — 지금 무슨 모델로 도는지, 컨텍스트·사용 한도를 얼마나 썼는지를 상시 표시한다. 봇 동작에 필수는 아니고, **«보기 위해» 설치하는 것**이다.

claude 본체는 node 없이 도는데 이 상태줄만 node 로 돈다. VPS 기본 이미지엔 node 가 없어서 한 줄이 먼저 붙는다:

```
apt install -y nodejs
claude plugin marketplace add uppinote20/claude-dashboard
claude plugin install claude-dashboard@claude-dashboard
```

설치 후 봇 세션을 새로 띄우면(「고쳤으면 새 세션」 원칙 그대로) 화면 아래에 상태줄이 그려진다. 부수 효과 하나: 상태줄의 `0/1.0M` 같은 표시는 컨텍스트 플래그가 **실제로 적용됐다는 독립 증거**다 — 「플래그를 넣었다」와 「먹었다」를 화면이 구분해 준다.
