# tofu-hostinger — VPS 설치 코파일럿 (:vps · :cc · :bot · :std-bot)

## Overview

서버 구입부터 봇 24시간 상시화까지를 **코파일럿 방식**으로 안내한다: 명령은 언제나 **사람이 복사·실행**하고, 이 스킬은 ①다음 명령 안내 ②실행 결과의 성공/문제 판정 ③다음 단계 안내만 한다. 판정 데이터는 클라이언트 중립 YAML 매니페스트(`manifest/`)에 있으며 Claude Code 와 Codex CLI 가 같은 파일을 소비한다(→ [codex.md](codex.md)).

## 라우팅

| 서브커맨드 | 매니페스트 | 내용 |
|---|---|---|
| **`:help`** | [help.md](help.md) | **전체 안내 한 편** — 서버 구입부터 봇 24시간 상시화까지를 «읽으면서 따라하는» 형태로. 판정 왕복 없이 쭉 읽힌다 |
| `:vps` | [manifest/vps.yaml](manifest/vps.yaml) | 서버 구입(KVM 플랜) → SSH 접속 → 기본 도구 설치 |
| `:cc` | [manifest/cc.yaml](manifest/cc.yaml) | Claude Code CLI 설치·인증 (+선택: ThisCode 번들) |
| `:bot` | [manifest/bot.yaml](manifest/bot.yaml) | 봇 토큰·초대 → 코드 3파일 → 실행·24시간 상시화 → 내 봇 올리기(배포·구동) |
| `:std-bot` | [manifest/std-bot.yaml](manifest/std-bot.yaml) | **표준 봇**(Claude Code 본체 + 공식 discord 플러그인)을 VPS 에 올리기 — bun → 플러그인 → 토큰 → 온보딩 → 기동 → 접근 허용 → 왕복 |

전체 순서로 진행하면 `:help(통독 안내) → :vps → (:cc) → :bot 또는 :std-bot`. 사용자가 서브커맨드 없이 오면 현재 상태를 물어 시작 지점을 정한다.

### `:bot` 과 `:std-bot` 은 다른 루트다 (섞지 말 것)

| | `:bot` (수업용 미니 봇) | `:std-bot` (표준 봇) |
|---|---|---|
| 실행기 | python + `bot.py` | Claude Code 본체 + bun |
| 토큰 변수명 | `DISCORD_TOKEN` | **`DISCORD_BOT_TOKEN`** |
| 토큰 경로 | `/opt/bot/.env` | **`~/.claude/channels/discord/.env`** |
| 접근 제어 | 없음(아무 멘션에나 응답) | **있음 — 허용 목록을 안 열면 완전 침묵** |
| 응답 형태 | 정해진 명령어(`핑`·`검색`) | 대화형 |

**승급 경로**로 쓴다: `:bot` 으로 "봇이 도는 것"을 먼저 체감시키고 → `:std-bot` 으로 실제 운영 봇을 올린다.
두 루트를 한 흐름에 섞으면 학습자가 "지금 내가 어느 쪽 지시를 따르는지"를 잃는다(루돌프 설계 판단 2026-08-20).
미니 봇 방(`mini-bot`)과 표준 봇 방(`bot`)은 이름이 달라 충돌하지 않는다.

## 코파일럿 계약 (판정 규율 — 위반 금지)

1. **자동 설치 ❌**: 서버에서 명령을 대신 실행하지 않는다. 매 단계 = 행동 지시 제시 → 사람이 실행·결과 붙여넣기 → 판정.
2. **판정 = 매니페스트의 「확인 명령 + 결정적 기대값」만**: 각 entry 의 `observation`(읽기 전용 확인 명령)을 사람이 실행한 출력이 `expected` 와 일치해야 PASS. 일치하면 다음 entry 로.
3. **불일치 시** = entry 의 `mismatch` 분기를 제시하고 사람 판단에 위임. 자유 텍스트 진단(에러 붙여넣기 해석)은 허용하되 **진단은 판정을 대체하지 못한다** — 진단 후에도 확인 명령 재통과가 게이트. 무한 재시도·조용한 건너뛰기 ❌ — 건너뛰기는 사람의 명시 선택 + 기록이 있을 때만.
4. **시크릿 무출력**: 토큰·비밀키 값을 채팅에 출력·요청하지 않는다. 확인은 항상 값이 안 보이는 방식(`grep -c`, 권한 확인). 화면 공유·녹화 중이면 토큰 구간에서 멈췄다 재개하도록 안내.
5. **`verified` 라벨 해석**: `measured`(라이브 서버 실측 통과 이력 있음) / `pending`(문서 근거는 있으나 기대값 실측 전 — 판정 시 출력이 기대와 조금 달라도 형태가 맞으면 PASS 후보로 보고하되, 라벨을 사람에게 고지). 미실측을 실측처럼 말하지 않는다.
   - ⚠️ **축 한정 measured 주의**: `measured` 옆에 조건 주석(`# … 축 한정`, `# … 기준`)이 붙은 항목은 **그 축에서만** 실측이다. 다른 축은 여전히 미검증이므로, 사람이 그 축으로 시험 중이면 「이 축은 아직 안 재봤다」를 먼저 고지하라. 라벨만 보고 전 축 통과로 읽지 말 것.
     - 실제 사례: std-bot `s7`(왕복)은 «봇 계정 발신»과 «사람 계정 발신»이 서로 다른 경로다(전자는 J-2 패치 필요, 후자는 무관). 한동안 앞 축만 실측이라 축 한정 라벨을 달았고, 2026-08-20 뒤 축까지 실측되어 지금은 **두 축 모두 measured** 다. 축이 갈리는 항목은 이렇게 «어느 축이 닫혔는지»를 주석에 적는다.
6. 치환 자리 표기 = `<서버 IP>` 처럼 꺾쇠 — 사람에게 본인 값으로 바꾸게 안내.

## 진행 표시

단계마다 `[:route 단계 id — 제목] n/전체` 한 줄을 머리에 붙여 사람이 어디까지 왔는지 알게 한다. 세션이 끊겨 재개하면, 마지막 PASS 단계의 확인 명령부터 다시 통과시키고 이어간다.

## Common Mistakes

- 저가 「Business」 상품 구매 = 공유 호스팅이라 봇 불가 → 반드시 VPS 메뉴의 KVM 플랜 (vps.yaml v1 mismatch).
- 폴더째 scp 전에 `mkdir` 해 두면 한 층 중첩 → bot.yaml b6 의 규칙(폴더째 보낼 땐 mkdir 생략).
- 토큰 값이 비었거나 무효(만료·복사 누락) → `Improper token` (등호 앞뒤 공백은 봇이 자동 정리하므로 무관 — bot.yaml b1 mismatch 실측).
- 판정 없이 "될 것 같다"로 다음 단계 진행 — 계약 2 위반.

### 🔴 `:std-bot` 진단 원칙 — 「죽지 않고 조용히 안 되는 것」

이 루트의 고장은 대부분 **에러 없이 조용히 안 붙는다.** 그래서 "에러가 안 났으니 잘 된 것"이 여기서는 성립하지 않는다.
사람이 "봇이 죽었다"고 오진하는 자리가 전부 이 묶음 안에 있다 — 전문은 [manifest/std-bot.yaml](manifest/std-bot.yaml) 하단 함정 층 참조.

- **A군 — 무징후 6종**: bun 부재 · 토큰 변수명/경로 · 허용 목록 빈값 · 채널 미초대 · 실패한 세션 · 패치를 엉뚱한 층에.
  이 중 **「실패한 세션」과 「패치 층」이 가장 악질** — 나머지는 고치면 풀리는데 이 둘은 *고친 뒤에도 그대로*라 사람이 자기 수리를 의심하게 만든다.
  공통 진단 질문 = **「내가 고친 자리가, 실제로 실행되는 자리인가?」**
- **B군 — 대조군 1종**: root 계정 거부. 이건 *즉시 죽고 이유도 말해준다.* A군을 설명할 때 반례로 쓴다("이건 이렇게 알려주는데, 나머지 여섯은 안 알려준다").
- **C군 — 자동화 전용 1종**: 온보딩 마법사. 대화형 첫 실행만 뜨므로 스크립트에서만 멈춘다.
